BigQuery / DBT (non-Terraforming / table creation)
==================================================
	01) Create BQ / dbt branch
	02) Develop BQ / dbt project (pushing to branch as applicable)
	03) Create GitHub PR
	04) Request Code Review in "Code Review Request" Teams channel (initial PR review by someone on the team or in the general CR review channel / before reaching out to QA)
	05) Once approved by 1st PR review person (developer), update card to be "Ready for Testing"
	06) Request QA review in "Quality Assurance" Teams channel (put link to PR in "Description" section of Jira card & send Jira card link to QA)
	07) Once QA passes, QA will put card in "Ready for Stage"
	08) Request in "Final PR Review Request" Teams Channel (Dev, Stage, INT) -- DBT PR review approval / 2nd required approval (3rd if counting QA + dev & dbt approver) comes from this requst
	09) Once all approve, I will be notified to click "Merge" (Dev, Int, & Stage)
	10) Notify QA merge is complete & perfrom Dev & Stage review
	11) Update Jira card to be "Stage Testsing" state
	12) QA will notify PO for PO review
	13) QA will update Jira card to be in UAT state
	14) QA / PO will notify of PO review is good
	15) Create "Production" PR (base:production / compare:develop)
	16) Request GitHub PR review "Final PR Review Request" Teams Channel (let them know it's a production PR review)
	17) Once approved, I will be notified to click "Merge" (into "Production" repo branch)
	18) Change story status to In Prod
	19) Notify QA for Prod review
	20) Once QA approves, QA closes story

BigQuery Terraforming (Tables)
==============================

	01) Clone "bq-landing-talend-dea-iac" repository (Bit Bucket / https://code.uwm.com/projects/DLIAC/repos/bq-landing-talend-dea-iac/)
	02) Create branch (in above noted repository) for work releating to Jira card in question (following normal branch-naming conventions)
	03) Create "CREATE TABLE" SQL script - NOTE the following requirements:
		03a) NO commenting in scripts
		03b) ONLY include the CREATE TABLE command (and associated columns, data types, etc.) - NOTHING else
		03c) The SQL script must be saved in the root / parent repository folder ("C:\Git_Repositories\bq-landing-talend-dea-iac" in my case)		
	04) In VS Code, open Git Bash prompt
	05) Issue command: cd nonprod
	06) Issue command: python "C:\Git_Repositories\bq-landing-talend-dea-iac\prepare_sql_data.py" "C:\Git_Repositories\bq-landing-talend-dea-iac\Scripts\Form1120S_Question_Mapping.sql"
		06a) CLI output will display creation of JSON and YML - 
				2026-08-04 09:53:16,959 - INFO - Generated JSON schema: tables\Form1120S_Question_Mapping.json
				2026-08-04 09:53:16,960 - INFO - Processed table 'Form1120S_Question_Mapping' in dataset 'BoltAudit' from file 'C:\Git_Repositories\bq-landing-talend-dea-iac\Form1120S_Question_Mapping.sql'
				2026-08-04 09:53:16,963 - INFO - Wrote dataset YAML: datasets\BoltAudit.yaml
	07) In "C:\Git_Repositories\bq-landing-talend-dea-iac\nonprod", confirm:
		07a) <table_name>.json
			07a1) Remove (the entire line) for the "description:" tag of "CreatedDateTime" column (this column is auto-generated by prepare_sql_data.py)
		07b) <table_schema>.yaml
			07b1) "name" tag = "id" tag
			07b2) "clustering", "table_constraints", "time_partitioning", "range_partitioning", and "expiration_time" will only have child-entries if the parent tag is applicable (e.g., "clustering" will have child entries only if there are column(s) that were clustered for the table in question, etc.) - otherwise, the value(s) for these tags will be NULL
			07b3) "talend_job_name" (child-entry in "labels" tag) will start off as "landingdea_" followed by value from "name" and / or "id" tags followed by two underscores ("__") and then finally followed by table name
	08) Commit & push local changes to feature branch in question
	09) Create PR
	10) Put link to PR in "Description" section of Jira card
	11) Request CR in "Code Review Request" Teams channel
	12) Once approved, request QA review in Quality Assurance" Teams channel
	13) Once QA approves, Request in "Final PR Review Request" Teams Channel (NOTING this review is for "nonprod")
	14) Once approved, merge feature branch into "master" branch in Bit Bucket
	15) Create branch (in above noted repository) for work releating to Jira card in question (following normal branch-naming conventions)
	16) -Can re-use SQL script from step #03 above-
